Using Helion

This is the user guide: open a design, run the CAD, read timing, simulate. Build steps live on Start.

What you get

  • Desktop IDE: Helion.app → Contents/MacOS/Helion (same as helion-ide)
  • CLI: helion (doctor, run, report_timing, project)
  • Part: HL10T-C32-1 from HAD, not a vendor die

Open a design in the IDE

  1. open dist/Helion.app (or cargo run -p helion-gui --bin helion-ide).
  2. Do not launch the CLI binary as the app.
  3. Open HDL from the examples rail: counter.sv, blinky.sv, hier.sv, complex.sv, or ysyx_ibex.sv.
  4. The Editor canvas shows the source. Device canvas is the floorplan of HL10T-C32-1 (IO ring, clock spine, CLB array). Timing canvas is STA.

Headless (no window) — this is the gold gate:

cargo run -p helion-gui --bin helion-ide -- --headless examples/counter.sv
# expect: WNS_PS=9640

CLI flow

cargo run -p helion-cli -- doctor
cargo run -p helion-cli -- run examples/counter.sv --cycles 16
cargo run -p helion-cli -- report_timing examples/blinky.sv

Empty-XDC counter gold: WNS_PS=9640. Fabric LED over 16 cycles: LED[16]=0000000111111110 (LED = cnt[3]).

Device (the die)

HAD grid for HL10T-C32-1:

In the app, Device is a canvas that fits the remaining pane (not a tiny bottom scroller). Package and Bitstream sit with it.

What “gold” means

If you change CAD or GUI, helion-ide --headless examples/counter.sv must still print WNS_PS=9640 unless the same commit updates the QoR table in the README with a reason.

Large SystemVerilog

examples/ysyx_ibex.sv is on the Open rail. Ingest is helion-sv. Fitting a full SoC on this part is not the synth bar. Leftover Helion-legal constructs should still map; do not abort the run because sv-parser is unhappy.
