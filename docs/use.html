What you get

BinaryWhat it is
helion-ideThe desktop IDE (Helion.app on macOS), plus windowless modes for scripts and CI
helionThe command-line tool: synthesis, implementation, reports, simulation, projects, IP, hardware
helion-progA small programmer front end over the hardware layer

All three drive the same engine crates. helion gui launches the IDE installed next to the CLI.

The IDE

The window follows the layout of commercial FPGA tools. The Flow Navigator on the left walks the flow in order: Project Manager, IP Integrator, High-Level Synthesis, Simulation, RTL Analysis, Synthesis, Implementation, Program and Debug. Sources lists the project's HDL, constraints and testbenches. The center pane shows one view at a time, or several as tabs, and the console at the bottom is a Tcl prompt with message filters. Docks resize and hide, and layouts are saved.

Keyboard

⌘P opens the command palette on files and ⇧⌘P on commands; ⌘K shows every shortcut. ⌘↩ runs implementation, ⌘1, 2, 3 go to Editor, Device and Timing, and ⇧⌘F finds cells, ports and nets in the design. Shortcuts are listed with macOS keys.

Projects and runs

A project is a plain-text .prj file. The IDE's New Project wizard writes one; you can also write it by hand:

# examples/counter.prj
part HL10T-C32-1
read_sv examples/counter.sv
read_xdc examples/counter.sdc

Other directives include read_vhdl, read_c, read_ip, top, create_clock, set_property and create_pblock. The part picker lists only parts a backend can implement end to end.

Runs live in the Design Runs table: create runs with an implementation strategy, sweep placer seeds, queue them, compare metrics, and make one active. Runs write checkpoints and can run incrementally against the active one. Out-of-context module runs synthesize a module once and reuse it.

An implementation run whose routing is incomplete reports a critical warning and does not write a bitstream.

Simulation and verification

Testbenches are discovered from the project (*_tb.sv, *_tb.vhd) and run against the design on the event simulator. Class-based SystemVerilog testbenches and a documented UVM subset run on the helion-svtb engine; pick the UVM test in the Simulation pane. Results include pass/fail, file:line failures, a VCD for the Waveform view, and coverage.

helion-ide examples/counter.prj      # then Simulation > Run on counter_tb.sv

Examples to start from: examples/counter_tb.sv, examples/counter_tb.vhd and examples/uvm_counter/. Engine limits are reported as errors, never silently ignored: class-based testbenches are 2-state up to 64 bits and have no structs, covergroups or DPI.

On the command line, helion equiv golden.sv revised.sv runs SAT-based equivalence checking and helion synth --verify checks synthesis against its own input.

Hardware

The Hardware Manager opens a target over one of three cables:

CableWhat it reachesStatus
SimulatedThe HL10 fabric model through a simulated IEEE 1149.1 TAPTested
Native FTDIFTDI MPSSE cables (FT2232H, FT232H, Digilent on-board cables) through libusbChain scan verified on a ZedBoard Programming not yet verified
openFPGALoaderAny cable openFPGALoader supports, when it is installedNot yet verified on a board

The native engine picks Digilent's pin profile from the USB descriptor and samples TDO on the falling edge above 15 MHz; HELION_JTAG_READ_EDGE=rising|falling overrides. Tests never touch a connected board.

Debug cores: mark nets for debug in the schematic or with mark_debug, run Set Up Debug, implement, then use the hardware ILA, VIO dashboard and JTAG-to-AXI console. Configuration memory supports erase, blank check, program, verify, read back and boot.

open_hw_manager
open_hw_target -cable native      # or auto | sim | usb
get_hw_devices
program_hw

Windowless modes

For scripts and CI, helion-ide runs without a window on the same Tcl interpreter as the console:

CommandWhat it does
helion-ide --headless <file>Synthesize, place, route and report timing for a source or .prj; prints WNS_PS
helion-ide --source script.tclRun a Tcl script in batch mode; exit status 1 on the first error
helion-ide --stdinTcl console on standard input, one command per line (quit ends)
helion-ide --versionVersion line
helion-ide --doctorTarget triple, bundled device data, self-check

The default part is HL10T-C32-1. helion --help prints the full list with every option.

Tcl console

The console is a real Tcl interpreter: variables, procedures, loops, expr, lists and catch, with errors reported as ERROR: ... (line N). On top of the language it has the object model (get_cells, get_nets, get_pins, get_ports, get_clocks, get_property, set_property), flow commands (read_sv, synth_design, opt_design, place_design, route_design, write_bitstream, write_checkpoint, launch_runs), every report, and the hardware, ECO and DFX verbs. The full list is in the Tcl reference; help in the console prints usage for any command.

read_sv examples/counter.sv
synth_design
place_design
route_design
report_timing -max_paths 5
write_bitstream counter.hbits

Constraints

Timing and I/O constraints use the XDC/SDC command set listed on the Architecture page: clocks, generated clocks, I/O delays, false paths, multicycle paths, min/max delays, clock groups and pin properties. The Constraints Wizard writes them for you, and the Timing Constraints view shows what was parsed.

IP packages

Helion IP packages are text manifests (.helion) next to their HDL. Buses are Helion-MM and Helion-ST. Load one in a project with read_ip, or browse them in the IP Catalog.

helion ip list
helion ip show ip/h_gpio/h_gpio.helion
helion project run examples/ip/read_ip_counter.prj --cycles 16

What gold means

The empty-XDC examples/counter.sv on HL10T-C32-1 at a 10 ns clock implements to 4 LUTFF and 1 IOB with WNS_PS=9640, and its LED over 16 cycles is LED[16]=0000000111111110. If a change to CAD or the IDE moves these, the same commit updates the QoR tests and says why.
