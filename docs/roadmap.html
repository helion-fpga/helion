What 4.0 delivers

  • A new IDE. helion-ide is rebuilt on the Rune UI framework, with Flow Navigator, Sources, Summary, device view with I/O planning and pblocks, schematic, timing, waveform, simulation, coverage, Hardware Manager, IP catalog and block design, HLS, ECO, DFX and out-of-context runs, reports, a Tcl console, a command palette and language templates.
  • Two Lattice backends. iCE40-HX8K on IceStorm data and ECP5 LFE5U-85F on Trellis data, next to HL10 and Xilinx 7-series.
  • Verification. Class-based SystemVerilog testbenches with a UVM subset, VHDL testbenches, and line and branch coverage of the design under test.
  • Windowless modes for scripts and CI: --headless, --source, --stdin, --version, --doctor.
  • A self-contained build. Rune vendored in third_party/rune, Rust 1.99.1 pinned, Cargo.lock enforced.
  • Native JTAG on real hardware. Chain scans verified on a ZedBoard from 1 to 30 MHz, with a Digilent pin profile and falling-edge sampling above 15 MHz.
  • The egui IDE is removed. helion-ide is the Rune IDE.

Every change is listed in the changelog.

After 4.0

Ordered roughly by priority. None of these has a date.

Hardware

  • Verify programming over the native FTDI cable on a board (scanning is verified; programming is not).
  • Status readback when programming through openFPGALoader.
  • Load iCE40, ECP5 and 7-series bitstreams on real boards; today they are checked against the open toolchains only.

Quality of results

  • Calibrate the timing models against measured data, then make pack, place and route fully timing-driven. The 7-series model is preliminary.
  • Bring the optimization passes added in the October campaign (priority-cut mapping, SAT sweeping, carry-chain extraction, timing-driven routing, detailed placement, path-based analysis) into the default flow, each behind the QoR tests.
  • Close the remaining buckets from the 1,000-design corpus: latch cells, primitive wrappers, enable folding.

IDE

  • A clock-region layer (needs a region model in HAD), pblock deletion, DFX partitions saved in the project, horizontal scrolling for very large files, richer VHDL diagnostics.
  • Wider testbench support: 4-state and wide values, structs, covergroups and DPI in class-based testbenches.

Project

  • Make the full workspace test run a required CI check; today the IDE, hardware and gold checks are required.
  • Notarized macOS builds, once an Apple Developer ID is available.
  • More maintainers. See Get involved.

The canonical copy of this plan is ROADMAP.md; issues are tracked in milestones.
