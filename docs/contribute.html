Your first change

  1. Agree on the approach

    For anything beyond a small fix, open an issue or a Discussion first, or pick a good first issue.

  2. Build and check

    Fork, branch from master, and follow Get started. Then run the checks CI requires:

    cargo test --locked -p helion-rune -p helion-hw
cargo run --locked -p helion-rune --bin helion-ide -- --headless examples/counter.sv
# WNS_PS=9640

  3. Make one focused change

    One concern, one crate when you can, with a test that fails without it. Iterate on a single test: cargo test -p CRATE --lib TESTNAME.

  4. Open a pull request

    Fill in the template, add a changelog line for anything users will notice, and get CI green.

Rules every pull request follows

  • Keep the gold. helion-ide --headless examples/counter.sv prints WNS_PS=9640. A deliberate QoR change updates crates/helion-cli/tests/qor.rs in the same commit, with the reason.
  • No echo-only UI. An IDE control does real work through the engines, or renders disabled with the reason.
  • Tests stay safe. They write only to the temp directory and never touch a connected board.
  • Vendored code stays vendored. Never edit third_party/rune in place; re-vendor with scripts/sync-rune.sh.
  • Stay inside the legal fence. No proprietary vendor IP, libraries or databases.

The full guide is CONTRIBUTING.md.
