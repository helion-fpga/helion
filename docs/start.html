Get started

Install a release or build from source, then check your install against the gold numbers. Helion runs on macOS (Apple Silicon) and Linux (x86_64).

Download a release

Every tagged release on GitHub Releases publishes the same set of files. The 4.0 release is in preparation; until it is tagged, the latest release is the 3.x line with the previous IDE.

FileContents
Helion-X.Y.Z-macos-arm64.zipHelion.app for Apple Silicon (ad-hoc signed, not notarized)
helion-X.Y.Z-aarch64-apple-darwin.tar.gzhelion, helion-ide, helion-prog, device data (HAD), examples
helion-X.Y.Z-x86_64-unknown-linux-gnu.tar.gzThe same for Linux x86_64
SHA256SUMS.txtChecksums for every file

On macOS, clear the quarantine flag once after moving the app to Applications:

xattr -cr /Applications/Helion.app

On Linux, the IDE needs libxkbcommon0, libwayland-client0 and libusb-1.0-0, which desktop distributions already ship.

Requirements for building

  • rustup and Git. The repository pins Rust 1.99.1 in rust-toolchain.toml; rustup installs it on the first build. Older compilers cannot build the workspace.
  • Nothing else from outside the clone: the Rune UI framework is vendored in third_party/rune (MIT) and Cargo.lock pins every crates.io dependency.
  • Linux: the system libraries the IDE and the native JTAG driver link against.
  • macOS: Xcode Command Line Tools, to assemble Helion.app.
sudo apt-get install pkg-config libxkbcommon-dev libwayland-dev libusb-1.0-0-dev   # Debian/Ubuntu
sudo dnf install pkgconf libxkbcommon-devel wayland-devel libusb1-devel            # Fedora

Build from source

git clone https://github.com/helion-fpga/helion.git
cd helion
cargo build --release --locked -p helion-cli -p helion-rune
./target/release/helion --version        # CLI
./target/release/helion-ide --help       # IDE, and its windowless modes

The first build compiles the whole workspace and takes a while. Later builds are incremental.

First run

Check the install against the gold numbers. Both must match exactly:

helion-ide --headless examples/counter.sv
# WNS_PS=9640
helion run examples/counter.sv --cycles 16
# LED[16]=0000000111111110
helion-ide --doctor        # target triple, bundled device data, self-check

Then open the IDE. With no arguments it shows the Start page with recent projects and the bundled examples; with a path it opens that project or source.

helion-ide
helion-ide examples/counter.prj

From a checkout without installing, prefix the commands with cargo run --release -p helion-cli -- or cargo run --release -p helion-rune --bin helion-ide --.

The macOS app

./scripts/build-macos-app.sh
open dist/Helion.app
Path in Helion.appWhat
Contents/MacOS/HelionThe IDE (helion-ide), launched by Finder
Contents/MacOS/helion-ideThe same binary under its usual name, for the windowless modes
Contents/MacOS/helion-cliThe CLI (named so it does not collide with Helion on case-insensitive disks)
Contents/Resources/devices/helionDevice data (HAD)
Contents/Resources/examplesBundled example designs and projects

The build script ad-hoc signs the bundle and stamps the version from Cargo.toml.

Where device data comes from

The HL10 part database (HAD) is looked up in this order: the HELION_HAD environment variable, next to the executable, Helion.app/Contents/Resources, the working directory, then the source tree the binary was built from. The iCE40 and ECP5 databases are built into their backends. The Xilinx 7-series backend reads the Project X-Ray database from $HELION_XILINX_DB; the part appears in the New Project picker only when that database is present.
